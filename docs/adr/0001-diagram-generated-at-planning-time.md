# Diagram is generated at planning time, stored as mermaid source, rendered client-side

The project diagram (architecture flowchart) is written by Claude during the `/linear-plan` pipeline from the spec, sent as plain mermaid source in the project payload, and rendered in the browser with the `mermaid` npm package. The app itself never generates or re-derives diagrams — no LLM calls, no server-side rendering, no mmdc/Kroki. We picked this over app-side generation because the spec context that makes a good diagram only exists at planning time, and over server-side rendering because client-side re-render is what makes per-task node highlighting instant. Consequence: hand-pasted plans have no diagram (the UI must degrade gracefully), and each task carries the diagram node ids it touches (`diagramNodes`) because the mapping can't be derived from task text later.
